## 2. Objetivo da Task
Montar o composition root: `cmd/server/main.go` que sobe o servidor gRPC via uber-fx, encadeando os módulos (db, auth, nationalteam) e a cadeia de interceptors (recovery → logging → protovalidate → auth), com lifecycle gerenciado e fail-fast de config. Entregar o helper E2E `TestNewBufconnServer`, os testes E2E de ponta a ponta e a verificação de build cross-platform (CT-033).

---

## 3. Descrição Detalhada

Conforme §3.1, §10.2, §11.6, §16.2 e §19.3 do Tech Spec:

- **`cmd/server/main.go`**: `fx.New(...)` incluindo `config`, `logger`, `db.Module`, `auth.Module`, `nationalteam.Module` e o servidor gRPC. No `OnStart`: validar config (fail-fast `JWT_SECRET` — T3, aborta o start), aplicar migrations (via db module), registrar `AuthServiceServer` e `NationalTeamServiceServer`, montar a cadeia unária **recovery → logging (T4) → protovalidate (T10) → auth JWT (T10)**, iniciar o listener na `GRPC_PORT`. No `OnStop`: shutdown gracioso + fechar DB. O bind `NationalTeamRepository` (concreto T9) → interface (AuthService T7) é resolvido aqui pelo fx.
- **`internal/testutil/bufconn.go`**: `TestNewBufconnServer(t)` — sobe o servidor com interceptors reais via `bufconn`, retorna conn + teardown. Reutilizado por CT-027..CT-032.
- **`test/e2e/auth_e2e_test.go`** e **`test/e2e/national_team_e2e_test.go`**: fluxos E2E black-box (§19.3).
- **Verificação de build** (CT-033): `make build-all` com `CGO_ENABLED=0` compila os 4 targets (prova de portabilidade — ADR-0001).

## 6. Testes

#### Integração cross-module: fluxo Register + wiring (`internal/auth/wiring_test.go`)

Setup: `TestNewDB` + módulos auth e nationalteam reais (ou grafo fx) (boundary: db/fx).

| CT | Teste | CA | Objetivo | Fluxo | Validação |
|----|-------|----|----------|-------|-----------|
| CT-022 | TestIntegration_Register_Login_JWT | CA-01, CA-05, CA-08 | Verificar fluxo Register→Login na stack real | Register (seleção do seed) → Login | JWT verificável; hash no DB |
| CT-026 | TestIntegration_PasswordHash_RealDB | CA-08 | Verificar que a senha persistida é hash, nunca texto legível | Register; ler senha_hash no DB | hash ≠ senha original |
| CT-034 | TestIntegration_UUIDv4_Unique | CA-01 | Verificar que ids gerados são UUID v4 válidos e únicos | 2 Registers consecutivos | usuarios.id UUID v4 e distintos |
| CT-035 | TestIntegration_FxWiring_Smoke | CA-09 | Verificar que o grafo fx (auth+nationalteam+db) monta sem erro | sobe grafo fx com DB in-memory | montagem sem erro (smoke wiring) |

#### Fluxo E2E: Register (CT-027) — `test/e2e/auth_e2e_test.go`
- **CA**: CA-01, CA-09
- **Objetivo**: validar que o cadastro funciona ponta a ponta pelo servidor real com interceptors.
- **Pré-condições**: server bufconn + seed aplicado.
- **Passos**: 1) `Register` com dados válidos; 2) recebe `user_id`.
- **Validações**: status OK, `user_id` não vazio.

#### Fluxo E2E: Register validação (CT-028)
- **CA**: CA-03 — **Objetivo**: campo ausente é barrado pelo interceptor protovalidate real (não chega ao handler).
- **Validações**: `codes.InvalidArgument`.

#### Fluxo E2E: Register → Login → RPC protegido (CT-029)
- **CA**: CA-01, CA-05, CA-07 — **Objetivo**: validar o ciclo completo de autenticação.
- **Passos**: 1) `Register`; 2) `Login` → token; 3) `GetMe` com `Bearer <token>`.
- **Validações**: `GetMe` retorna dados do usuário; fluxo OK.

#### Fluxo E2E: RPC protegido sem token (CT-030)
- **CA**: CA-07 — **Objetivo**: `GetMe` sem metadata ⇒ `Unauthenticated`.

#### Fluxo E2E: RPC protegido com token expirado (CT-031)
- **CA**: CA-07 — **Objetivo**: token com exp no passado (Clock injetado) ⇒ `Unauthenticated`.

#### Fluxo E2E: ListNationalTeams público (CT-032) — `test/e2e/national_team_e2e_test.go`
- **CA**: CA-10 — **Objetivo**: `ListNationalTeams` **sem** token retorna seleções do seed (RPC público).
