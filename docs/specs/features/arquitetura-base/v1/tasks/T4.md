## 2. Objetivo da Task
Prover um logger estruturado (zap) e um interceptor gRPC unário de logging que registra RPC recebido/respondido com `rpc`, `code`, `duration_ms`, sem vazar dados sensíveis (senha, hash, token).

---

## 3. Descrição Detalhada

Conforme §13.1 (Logs Estruturados) e §10.3 do Tech Spec:

- **`internal/logger/logger.go`**: construtor do `*zap.Logger` estruturado (JSON). Nível configurável (default info). Exposto para injeção via fx.
- **`internal/logger/interceptor.go`**: `grpc.UnaryServerInterceptor` que loga início/fim do RPC com campos `rpc`, `code` (status), `duration_ms`. Erros de domínio em `warn`, erros internos em `error`. **Nunca** logar senha plana, `senha_hash` ou JWT completo (§10.3, §13.1).
- O interceptor é encadeado na cadeia unária (recovery → logging → protovalidate → auth) montada no composition root (T12).

Match de estilo: seguir o padrão de logs estruturados do projeto (campos zap tipados, não `Sugar` quando evitável).
