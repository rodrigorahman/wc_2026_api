## 2. Objetivo da Task
Implementar o `AuthService` com as regras de cadastro e login: validação de seleção, unicidade de e-mail, hash bcrypt (cost 12), geração de UUID v4, emissão de token (via interface `TokenManager`) e **equalização de timing** no login (anti-enumeração de e-mails). Declara as interfaces de dependência no pacote consumidor (placement idiomático Go).

---

## 3. Descrição Detalhada

Conforme §5.1 (Fluxos), §6.3 (Regras de Domínio) e §11.3 do Tech Spec:

- **`internal/auth/service/auth_service.go`**:
  - Declarar **no pacote service** as interfaces consumidas (placement no consumidor — §3.3): `UserRepository` (`CreateUser`, `GetUserByEmail`), `NationalTeamRepository` (`GetNationalTeamByID`), `TokenManager` (`Generate`). Injetar `Clock` (T6).
  - **Register**: validar seleção existe via `GetNationalTeamByID` → inexistente ⇒ `status.Error(codes.InvalidArgument, ...)` (RN3/RN4); validar e-mail livre via `GetUserByEmail` → existente ⇒ `codes.AlreadyExists` (RN1); gerar hash bcrypt **cost 12** (RN2); gerar **UUID v4** (`crypto/rand`); chamar `CreateUser`; retornar `user_id`.
  - **Login**: `GetUserByEmail`; se não encontrado **ou** senha inválida ⇒ `codes.Unauthenticated` com **mensagem genérica idêntica** (RN5). **Anti-timing**: no caminho "e-mail inexistente", executar mesmo assim `bcrypt.CompareHashAndPassword` contra um **hash dummy fixo** (gerado no boot/init do service) antes de retornar (§5.1/§11.3). Credenciais válidas ⇒ `TokenManager.Generate`.
  - Definir erros de domínio internos quando útil (`ErrInvalidNationalTeam`, `ErrDuplicateEmail`, `ErrInvalidCredentials`), mas o service retorna `status.Error` com os códigos gRPC conforme §10.1 (as tabelas §19 esperam `codes.X` no retorno do service).
- **bcrypt cost configurável** (10 em CI, 12 prod) se hash >500ms no CI (recomendação QA §19.4) — via parâmetro do construtor, default 12.

Service unit-testável com mocks das 3 interfaces + `Clock` (gate No Self-Set Mock respeitado: assertion sobre o hash capturado, não sobre retorno de mock).
