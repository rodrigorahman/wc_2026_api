## 2. Objetivo da Task
Implementar os dois interceptors unários cross-cutting: (1) **protovalidate** — valida as mensagens proto (regras `buf.validate`) barrando requests inválidas antes do handler; (2) **auth JWT** — extrai `authorization: Bearer <token>` da metadata, valida via `TokenManager` e injeta claims no `context` para RPCs protegidos.

---

## 3. Descrição Detalhada

Conforme §3.1 (cadeia de interceptors), §5.1 (acesso protegido), §11.1 do Tech Spec:

- **`internal/auth/interceptor/protovalidate.go`**: `UnaryServerInterceptor` que valida a mensagem de request com `protovalidate` (bufbuild). Falha ⇒ `status.Error(codes.InvalidArgument, <detalhe>)` **sem** invocar o handler.
- **`internal/auth/interceptor/auth_jwt.go`**: `UnaryServerInterceptor` (base `go-grpc-middleware/auth` v2) que:
  - Extrai `authorization: Bearer <jwt>` da metadata.
  - Valida via `TokenManager.Validate` (assinatura, exp, alg) — ausente/inválido/expirado ⇒ `codes.Unauthenticated`, handler não chamado.
  - Válido ⇒ injeta `sub` (user_id) no `context` (chave tipada).
  - Aplica-se **apenas a RPCs protegidos** (ex.: `GetMe`); `Register`/`Login`/`ListNationalTeams` permanecem públicos (lista de métodos públicos ou seletor por método). Usa `Clock` (T6) para determinismo.

Verificações de erro via `errors.Is`/códigos gRPC. Não logar o token.
