## 2. Objetivo da Task
Implementar o `AuthHandler` gRPC (mapper proto↔domínio para `Register`/`Login`/`GetMe`) e o `fx.Module` do domínio auth, que provê handler, service, repository, token manager e interceptors, fazendo o bind concreto→interface. O handler é mapper puro — o mapeamento erro→status já vem do service (§10.1).

---

## 3. Descrição Detalhada

Conforme §3.2, §4.1, §5.1 e §6.2 do Tech Spec:

- **`internal/auth/handler/auth_handler.go`**: implementa o `AuthServiceServer` gerado:
  - `Register`: mapeia `RegisterRequest` → input de domínio → `AuthService.Register` → `RegisterResponse{user_id}`.
  - `Login`: mapeia `LoginRequest` → `AuthService.Login` → `LoginResponse{access_token, expires_at}` (`time.Time` → `google.protobuf.Timestamp`).
  - `GetMe`: lê `sub` do `context` (injetado pelo interceptor JWT, T10) e retorna `GetMeResponse{user_id, full_name, email, national_team_id}`.
  - Erros do service já vêm como `status.Error(codes.X)` — propagar sem retraduzir.
- **`internal/auth/module.go`**: `fx.Module("auth", ...)` que provê `AuthService` (T7), `UserRepository` concreto (T8) **bind à interface** do service, `TokenManager` (T6), `AuthHandler` e os interceptors (T10). Declara a dependência `NationalTeamRepository` (satisfeita pelo módulo nationalteam no composition root — T12).
- Registrar o `AuthServiceServer` no servidor gRPC é feito no composition root (T12); aqui apenas o módulo provê os componentes.
