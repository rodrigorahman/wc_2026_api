## 2. Objetivo da Task
Implementar o `TokenManager` que emite e valida JWT HS256 (claims `sub`/`exp`, TTL configurável), com validação estrita de algoritmo (rejeita `none`/RS256 — defesa contra alg-confusion). Introduz a interface `Clock` injetável para determinismo de tempo.

---

## 3. Descrição Detalhada

Conforme §11.1 (Autenticação), §11.3 e §5.1 do Tech Spec:

- **`internal/clock/clock.go`**: interface `Clock { Now() time.Time }` + implementação real (`systemClock`). Compartilhada com `AuthService` (T7) e interceptor JWT (T10) para determinismo de testes (recomendação QA §19.4).
- **`internal/auth/token/token_manager.go`**: `TokenManager` com secret (HS256) e TTL injetados:
  - `Generate(userID string) (token string, expiresAt time.Time, err error)` — claims `sub`=userID, `exp`=`clock.Now()+TTL`. Algoritmo HS256.
  - `Validate(token string) (userID string, err error)` — valida assinatura, expiração e **algoritmo esperado** usando `jwt.NewParser(jwt.WithValidMethods([]string{"HS256"}))` (rejeita `none` e RS256). Usa `clock.Now()` para checagem de expiração.
  - Erros sentinela mapeáveis: token expirado / assinatura inválida / algoritmo não permitido.

golang-jwt v5. Verificações de erro via `errors.Is` (não string match).
