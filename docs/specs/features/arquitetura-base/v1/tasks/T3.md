## 2. Objetivo da Task
Implementar o carregamento de configuração via viper (`DB_PATH`, `JWT_SECRET`, `JWT_TTL`, `GRPC_PORT`), com **fail-fast no boot** que aborta a inicialização se o `JWT_SECRET` estiver ausente, vazio ou com menos de 32 bytes (§11.6) — evitando subir um servidor inseguro silenciosamente.

---

## 3. Descrição Detalhada

Conforme §11.6 (Secrets Management) e §16 do Tech Spec:

- **`internal/config/config.go`**: struct `Config` com campos `DBPath`, `JWTSecret`, `JWTTTL` (`time.Duration` ou segundos), `GRPCPort`. Função pública de carregamento (ex.: `Load() (Config, error)` ou `New(...)`) que lê via viper de env vars (e arquivo opcional).
- **Defaults** sensatos para `JWT_TTL` (1h) e `GRPC_PORT` quando não definidos; `DB_PATH` obrigatório.
- **Fail-fast de segurança**: retornar `error` (NÃO `log.Fatal`/`os.Exit` interno — manter testável) se `JWT_SECRET` for ausente, vazio ou `len(secret) < 32` bytes. A mensagem deve indicar o requisito de tamanho mínimo. O caller (`cmd/server/main.go`, T12) decide abortar o `fx OnStart`.

Decisão de design (gate de testabilidade): `Load` é função pura `(Config, error)`; o efeito de abortar o boot fica no composition root.
