## 5. Testes

### 5.3 Testes E2E

Setup comum: `conn := testutil.TestNewBufconnServer(t, nil)` (cadeia de interceptors real, módulos reais incl. `match.Module` provisionado em T6); `matchv1.NewMatchServiceClient(conn)`. Sem partidas semeadas (helper não expõe `*sql.DB`). Reusar a constante `seededBrasilID` e o fluxo Register/Login de `auth_e2e_test.go` (mesmo pacote `e2e`).

#### Fluxo: ListUpcomingMatches sem token (CT-001)
- **Objetivo**: Validar ponta a ponta que o RPC é protegido — o interceptor JWT barra a chamada antes do handler (prova que `ListUpcomingMatches` não é público) (CA1).
- **Pré-condições**: servidor bufconn iniciado; contexto Go puro sem metadata `authorization`.
- **Passos**:
  1. `conn := TestNewBufconnServer(t, nil)`; `client := matchv1.NewMatchServiceClient(conn)`.
  2. `client.ListUpcomingMatches(context.Background(), &matchv1.ListUpcomingMatchesRequest{})`.
- **Validações**: `require.Error(err)`; `status.Code(err) == codes.Unauthenticated`.

#### Fluxo: ListUpcomingMatches autenticado sem favoritas → lista vazia (CT-002)
- **Objetivo**: Validar ponta a ponta que lista vazia **não é erro** atravessando toda a cadeia de interceptors (CA5).
- **Pré-condições**: nenhuma partida semeada; e-mail único por teste.
- **Passos**:
  1. `conn := TestNewBufconnServer(t, nil)`; clients de auth e match.
  2. `Register` (e-mail único, ex.: 1 favorita `seededBrasilID`) → `require.NoError`.
  3. `Login` → obter `access_token`.
  4. `authCtx := metadata.AppendToOutgoingContext(ctx, "authorization", "Bearer "+token)`.
  5. `matchClient.ListUpcomingMatches(authCtx, &matchv1.ListUpcomingMatchesRequest{})`.
- **Validações**: `require.NoError(err)`; `require.Empty(resp.GetMatches())` (len == 0).

## 6. Notas / Observacoes
- **Cobertura deliberada (SCOPE §5)**: E2E cobre o stack autenticado (token ausente; autenticado sem favoritas → vazio); o caminho-feliz **com partidas** fica na integração-repository (T3) porque `TestNewBufconnServer` não semeia `matches` nem expõe `*sql.DB` — decisão para não inflar `testutil`.
- O cenário "autenticado sem favoritas" pode usar um Register com favoritas cujas seleções não tenham jogos (nenhuma partida semeada ⇒ sempre vazio) — o ponto é provar `lista vazia ≠ erro` ponta a ponta.
- Esta task é só código de teste; não há produção nova (toda a produção foi entregue em T1–T6).
