## 2. Objetivo da Task
Definir o contrato gRPC do domínio `match` (request vazio — favoritas vêm do token, anti-IDOR), gerar os stubs e implementar o handler mapper puro proto↔domínio que lê o subject do contexto (RPC protegido, padrão `GetMe`). O handler propaga o erro do service como `codes.Internal` (mapper puro, sem retraduzir códigos).

## 6. Notas / Observacoes
- **Anti-IDOR (ADR-0003)**: o `userID` vem **somente** do `sub` do contexto, nunca do request (que é vazio). O teste deve montar contexto com e sem subject (injetar a chave de contexto do interceptor) e assertar `status.Code()`.
- O handler é **mapper puro**: não conhece regra de negócio nem o relógio; só traduz proto↔domínio e propaga o erro como `Internal`.
- `MatchTeam` é mensagem própria de `match.v1` (não importa `nationalteam.v1`) — contrato auto-contido, carrega `code`.
- O proto é gerado nesta task porque o handler é seu primeiro consumidor; a registração no `*grpc.Server` e o helper E2E ficam em T6.
