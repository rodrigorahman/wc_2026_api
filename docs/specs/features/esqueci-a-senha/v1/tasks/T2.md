## 2. Objetivo da Task
Estender o contrato proto `wc2026.auth.v1` com os dois RPCs novos da recuperação (`RequestPasswordRecovery`, `ChangePassword`) e o campo `password_change_required` no `LoginResponse`, todos **add-only** (sem realocar tags, sem breaking change), e regenerar os stubs via `make proto`.

## 3. Descrição Detalhada

### `api/proto/wc2026/auth/v1/auth.proto`
- No `service AuthService`, adicionar:
  ```proto
  rpc RequestPasswordRecovery(RequestPasswordRecoveryRequest) returns (RequestPasswordRecoveryResponse);
  rpc ChangePassword(ChangePasswordRequest) returns (ChangePasswordResponse);
  ```
- Mensagens novas:
  ```proto
  message RequestPasswordRecoveryRequest {
    string email = 1 [(buf.validate.field).string.email = true];
  }
  message RequestPasswordRecoveryResponse {
    string message = 1;
  }
  message ChangePasswordRequest {
    string temp_password = 1 [(buf.validate.field).string = { min_len: 1 }];
    string new_password  = 2 [(buf.validate.field).string = { min_len: 8 }];
  }
  message ChangePasswordResponse {}
  ```
- `LoginResponse`: adicionar `bool password_change_required = 3;` (tag 3, add-only; tags 1/2 inalteradas — §15.2).
- Seguir o estilo do `auth.proto` existente (validação declarativa `buf.validate`, snake_case nos campos, inglês).

### Regeneração
- `make proto` (buf) regenera `gen/wc2026/auth/v1/**`. Código gerado **não se edita à mão**.
- Após regen, os símbolos `AuthService_RequestPasswordRecovery_FullMethodName` e `AuthService_ChangePassword_FullMethodName` ficam disponíveis (consumidos em T9 para a lista de public methods).

> **Fora de escopo**: implementar os handlers (T8) e a lista de public methods no server (T9). Aqui só o contrato + stubs gerados.
