## 2. Objetivo da Task
Adicionar ao `AuthHandler` os mappers puros dos dois RPCs novos (`RequestPasswordRecovery`, `ChangePassword`) e propagar o campo `password_change_required` no `LoginResponse`. O handler permanece mapper puro: converte proto↔domínio e propaga o erro do service verbatim (sem retraduzir código gRPC).

---

## 3. Descrição Detalhada

### Interface `handler.AuthService` (em `auth_handler.go`)
Adicionar os métodos consumidos:
- `RequestPasswordRecovery(ctx context.Context, email string) (string, error)`
- `ChangePassword(ctx context.Context, userID, tempPassword, newPassword string) error`

### Handlers
- **`RequestPasswordRecovery`**: `msg, err := svc.RequestPasswordRecovery(ctx, req.GetEmail())`; propaga erro; retorna `&authv1.RequestPasswordRecoveryResponse{Message: msg}`.
- **`ChangePassword`**: lê `sub` via `interceptor.SubjectFromContext(ctx)` (idêntico a `GetMe`); ausente → `status.Error(codes.Unauthenticated, "não autenticado")`. Chama `svc.ChangePassword(ctx, sub, req.GetTempPassword(), req.GetNewPassword())`; propaga erro; retorna `&authv1.ChangePasswordResponse{}`.
- **`Login`** (modificado): preencher `PasswordChangeRequired: result.PasswordChangeRequired` no `LoginResponse` (campos existentes inalterados).

> Sem regra de negócio no handler. A validação de input (`email`, `min_len`) já é feita pelo interceptor protovalidate (T2). A proteção JWT do `ChangePassword` e o caráter público do `RequestPasswordRecovery` são configurados no server (T9).
