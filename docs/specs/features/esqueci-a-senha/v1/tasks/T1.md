## 2. Objetivo da Task
Adicionar a base de persistência da recuperação de acesso: as duas colunas nullable `temp_password_hash` e `temp_password_expires_at` na tabela `users` (migração 000009 aditiva), as queries sqlc para gravar/invalidar a senha temporária, e os métodos de repository correspondentes — com round-trip de leitura confirmando o que foi gravado e mapeamento correto de NULL → zero value.

---

## 3. Descrição Detalhada

### Migração 000009 (aditiva, nullable)
- `000009_add_temp_password_to_users.up.sql`:
  ```sql
  ALTER TABLE users ADD COLUMN temp_password_hash TEXT;
  ALTER TABLE users ADD COLUMN temp_password_expires_at TIMESTAMP;
  ```
- `000009_add_temp_password_to_users.down.sql`:
  ```sql
  ALTER TABLE users DROP COLUMN temp_password_expires_at;
  ALTER TABLE users DROP COLUMN temp_password_hash;
  ```
- Colunas sem default (NULL por padrão) — segura para rollout sem downtime; dados pré-existentes ficam com temp NULL.

### Queries sqlc (`internal/infra/db/queries/users.sql`)
- `GetUserByEmail` e `GetUserByID`: incluir `temp_password_hash, temp_password_expires_at` no `SELECT`.
- Nova `SetTempPassword :execrows` — `UPDATE users SET temp_password_hash = ?, temp_password_expires_at = ? WHERE id = ?`. Use `:execrows` para o repository detectar linhas afetadas (CT-019).
- Nova `UpdatePassword :execrows` — `UPDATE users SET password_hash = ?, temp_password_hash = NULL, temp_password_expires_at = NULL WHERE id = ?`. Zera as colunas temp no mesmo `UPDATE` (invalidação atômica — §7.4).
- Regenerar com `make sqlc`. As colunas nullable geram `sql.NullString`/`sql.NullTime` no struct gerado (verificar `models.go` após regen).

### Repository (`internal/domain/auth/repository/user_repository.go`)
- Struct `repository.User`: adicionar `TempPasswordHash string` e `TempPasswordExpiresAt time.Time` (zero-value quando NULL).
- `toUser(row sqlc.User)`: converter `row.TempPasswordHash` (`sql.NullString`) → `string` (vazio quando inválido) e `row.TempPasswordExpiresAt` (`sql.NullTime`) → `time.Time` (zero quando inválido).
- Novo método `SetTempPassword(ctx context.Context, id string, hash string, expiresAt time.Time) error`: chama a query; se `rowsAffected == 0` retorna `fmt.Errorf("set temp password: %w", ErrUserNotFound)`.
- Novo método `UpdatePassword(ctx context.Context, id string, hash string) error`: mesma semântica de 0 linhas → `ErrUserNotFound`.
- `withNationalTeams` permanece inalterado — apenas garantir que o scan das novas colunas (em `toUser`) não quebra com NULL (regression guard CT-038).

### Assinaturas canônicas (referência para T5 e T9)
- `SetTempPassword(ctx, id string, hash string, expiresAt time.Time) error`
- `UpdatePassword(ctx, id string, hash string) error`

> **Fora de escopo desta task**: `service.User`, a interface `service.UserRepository` e o `userRepositoryAdapter` (module.go) — tratados em T5/T9. Aqui só o concreto + schema + queries.

## 7. Notas / Observações
- `make sqlc` é mandatório após editar `users.sql` — o código gerado em `internal/infra/db/sqlc/**` não se edita à mão.
- `:execrows` (não `:exec`) nas duas queries de UPDATE é o que viabiliza o CT-019.
- As colunas geram `sql.NullString`/`sql.NullTime`; o mapeamento NULL→zero value vive em `toUser` — é o ponto que CT-022/CT-038 protegem.
- Não tocar em `service.User` nem no adapter (module.go) — isso é T5/T9.
