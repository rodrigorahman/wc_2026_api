## 2. Objetivo da Task
Estender `AuthService.Login` com o segundo branch de comparação (senha temporária) e o sinal `PasswordChangeRequired`: login pela senha original mantém acesso normal (`false`); login pela temporária ativa e não expirada concede acesso e sinaliza `true`; temp expirada/ausente cai no `Unauthenticated` genérico.

---

## 3. Descrição Detalhada

### `LoginResult` (em `auth_service.go`)
- Adicionar campo `PasswordChangeRequired bool`.

### `Login(ctx, email, password)` — lógica do 2º branch
Mantendo a equalização de timing anti-enumeração existente (dummy hash no e-mail inexistente):
1. `GetUserByEmail`; e-mail inexistente → compara dummy → `Unauthenticated` (inalterado).
2. Compara `password` contra `user.PasswordHash`. Casou → sucesso com `PasswordChangeRequired=false` (RN10/CA-10), inclusive quando há temp ativa ou expirada.
3. Não casou a original **e** há temp ativa não expirada (`TempPasswordHash != ""` **e** `s.clk.Now().Before(user.TempPasswordExpiresAt)`) → compara `password` contra `user.TempPasswordHash`. Casou → sucesso com `PasswordChangeRequired=true` (CA-04).
4. Caso contrário (incluindo temp expirada — fronteira: `expires_at == now` é negado, usa `Before`) → `Unauthenticated` genérico (CA-05).
- Mensagem de falha permanece `msgInvalidCredentials` (genérica, idêntica).
- Token emitido apenas no sucesso, via `tokens.Generate` (inalterado).

> **Boundary crítico** (CT-009): a checagem de expiração usa `clock.Now().Before(expires_at)` — o instante exato `expires_at == now` é **negado**.

> **Fora de escopo**: handler/proto (T8), `ChangePassword` (T7). Aqui só `Login`.

## 7. Notas / Observações
- A ordem dos branches importa: a original é testada **primeiro** — assim `PasswordChangeRequired=false` mesmo com temp ativa (CA-10/RN10).
- Não dobrar o custo bcrypt de todo login: o 2º compare só ocorre quando a original falha **e** há temp ativa (risco de timing aceito e documentado no tech_spec §20).
- `Before` (não `Before||Equal`) é a escolha consciente para a fronteira exata.
